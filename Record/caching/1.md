Spring Boot provides built-in caching abstraction that supports multiple cache providers like **ConcurrentHashMap (default)**, **Caffeine**, **EhCache**, **Redis**, **Hazelcast**, etc.

If you don't configure any cache provider, Spring Boot uses a simple **ConcurrentHashMap** cache (Simple Cache).

---

# 1. Dependency

For Spring Boot 3.x, add the cache starter.

### Maven

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-cache</artifactId>
</dependency>
```

---

# 2. Enable Caching

Add `@EnableCaching` to your main Spring Boot application.

```java
@SpringBootApplication
@EnableCaching
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }

}
```

Without this annotation, none of the cache annotations will work.

---

# 3. application.properties

For the default in-memory cache:

```properties
spring.cache.type=simple
```

or simply omit this property—Spring Boot will automatically use the simple cache if no other provider is on the classpath.

You can also pre-create cache names:

```properties
spring.cache.cache-names=users,products,orders
```

---

# 4. Cache Annotations

Spring Boot mainly provides four caching annotations:

| Annotation    | Purpose                                                                      |
| ------------- | ---------------------------------------------------------------------------- |
| `@Cacheable`  | Reads from cache first; if absent, executes the method and caches the result |
| `@CachePut`   | Always executes the method and updates the cache                             |
| `@CacheEvict` | Removes entries from the cache                                               |
| `@Caching`    | Combines multiple caching annotations                                        |

---

# 5. @Cacheable Example

```java
@Service
public class UserService {

    @Cacheable(value = "users", key = "#id")
    public User getUser(Long id) {

        System.out.println("Fetching from DB");

        return userRepository.findById(id).orElse(null);
    }
}
```

### First Call

```java
userService.getUser(10);
```

Output

```
Fetching from DB
```

### Second Call

```java
userService.getUser(10);
```

Output

```
(No DB call)
```

The result is returned from the cache.

---

# 6. @CachePut Example

Always updates the cache.

```java
@CachePut(value = "users", key = "#user.id")
public User updateUser(User user) {

    System.out.println("Updating DB");

    return userRepository.save(user);
}
```

Flow:

```
Client -> Method Executes -> Database Updated -> Cache Updated
```

---

# 7. @CacheEvict Example

Remove one cache entry.

```java
@CacheEvict(value = "users", key = "#id")
public void deleteUser(Long id) {

    userRepository.deleteById(id);
}
```

After deletion:

```
Cache removed

Next request -> DB Hit
```

---

## Remove All Entries

```java
@CacheEvict(value = "users", allEntries = true)
public void clearCache() {

}
```

---

# 8. @Caching

Combine multiple operations.

```java
@Caching(
    put = {
        @CachePut(value = "users", key = "#user.id")
    },
    evict = {
        @CacheEvict(value = "orders", key = "#user.id")
    }
)
public User updateUser(User user) {

    return repository.save(user);
}
```

---

# 9. Cache Key

Default:

```java
@Cacheable("users")
```

The method arguments become the cache key automatically.

Custom key:

```java
@Cacheable(value="users", key="#id")
```

Multiple parameters:

```java
@Cacheable(value="users", key="#name + '-' + #age")
```

Using an object:

```java
@Cacheable(value="users", key="#user.id")
```

---

# 10. Condition

Cache only if the condition is true.

```java
@Cacheable(value="users", condition="#id > 100")
```

Only users with IDs greater than 100 are cached.

---

# 11. unless

Skip caching based on the result.

```java
@Cacheable(value="users", unless="#result == null")
```

or

```java
@Cacheable(value="users", unless="#result.isEmpty()")
```

---

# 12. Sync Option

Prevent multiple threads from loading the same data simultaneously.

```java
@Cacheable(value="users", key="#id", sync=true)
```

If 100 requests come at once for the same key:

Without `sync`

```
100 Requests -> 100 DB Calls
```

With `sync=true`

```
100 Requests -> 1 DB Call -> 99 Threads Wait -> Cached Result Returned
```

---

# 13. CacheManager

You can inject the cache manager.

```java
@Autowired
private CacheManager cacheManager;
```

Example:

```java
Cache cache = cacheManager.getCache("users");

cache.put(1L, user);

User user = cache.get(1L, User.class);
```

# 14. Complete Example

```java
@Service
public class ProductService {

    @Cacheable(value = "products", key = "#id")
    public Product getProduct(Long id) {

        System.out.println("Loading from DB");

        return repository.findById(id).orElse(null);
    }

    @CachePut(value = "products", key = "#product.id")
    public Product updateProduct(Product product) {

        return repository.save(product);
    }

    @CacheEvict(value = "products", key = "#id")
    public void deleteProduct(Long id) {

        repository.deleteById(id);
    }
}
```

# 15. Interview Questions

### Q1. What is `@Cacheable`?

Checks the cache first. If the key exists, returns the cached value. Otherwise, executes the method and stores the result in the cache.

### Q2. Difference between `@Cacheable` and `@CachePut`

| @Cacheable                                  | @CachePut                  |
| ------------------------------------------- | -------------------------- |
| May skip method execution if data is cached | Always executes the method |
| Reads from cache                            | Updates the cache          |
| Best for read operations                    | Best for update operations |

### Q3. Difference between `@CacheEvict` and `@CachePut`

| @CachePut         | @CacheEvict                       |
| ----------------- | --------------------------------- |
| Updates the cache | Removes entries from the cache    |
| Used after update | Used after delete or invalidation |

### Q4. Is Spring Boot cache thread-safe?

Yes. The default `ConcurrentHashMap`-based simple cache is thread-safe. Production systems often use providers like Redis or Caffeine for better scalability and features.

### Q5. What cache providers does Spring Boot support?

* Simple (`ConcurrentHashMap`)
* Caffeine
* Redis
* EhCache
* Hazelcast
* JCache (JSR-107)
* Infinispan (with additional setup)

### Q6. When should you avoid caching?

Avoid caching:

* Frequently changing data
* Highly transactional data that must always be fresh
* Very large objects that can consume excessive memory

For distributed applications with multiple instances, use a shared cache such as **Redis** instead of the default in-memory cache, because each application instance maintains its own local cache.
