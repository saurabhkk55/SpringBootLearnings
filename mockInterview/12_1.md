# Java Memory Model in Java 8+: Heap, Stack, PermGen, Metaspace & Static Variables

One of the most misunderstood topics in Java is **where static variables are stored**. Many older books and tutorials say that *static variables are stored in the Method Area (PermGen)*. That was true for older versions of the HotSpot JVM, but **it is not the complete picture in Java 8 and later**.

This document explains the JVM memory model, the difference between **Heap**, **Stack**, **PermGen**, and **Metaspace**, and why static variables are treated differently in modern Java.

---

# JVM Memory Overview

When a Java application starts, the JVM divides memory into several regions.

```text
                    Computer RAM
+------------------------------------------------------------+
|                                                            |
|                    Java Process (JVM)                      |
|                                                            |
|  +--------------------+                                    |
|  | Heap               |  <-- JVM Managed                   |
|  |--------------------|                                    |
|  | Objects            |                                    |
|  | Arrays             |                                    |
|  | String Objects     |                                    |
|  | Class Mirror       |                                    |
|  | Static Variables   |                                    |
|  +--------------------+                                    |
|                                                            |
|  +--------------------+                                    |
|  | Thread Stack       |                                    |
|  |--------------------|                                    |
|  | Local Variables    |                                    |
|  | Method Frames      |                                    |
|  +--------------------+                                    |
|                                                            |
|  +--------------------+                                    |
|  | Metaspace          | <-- Native OS Memory               |
|  |--------------------|                                    |
|  | Class Metadata     |                                    |
|  | Method Metadata    |                                    |
|  | Runtime Constant   |                                    |
|  | Pool               |                                    |
|  +--------------------+                                    |
|                                                            |
+------------------------------------------------------------+
```

Notice that **both Heap and Metaspace ultimately use your computer's RAM**, but they are managed differently.

---

# Heap Memory

The Heap is the memory area managed by the **JVM Garbage Collector**.

It stores:

* Objects
* Arrays
* String objects
* Class mirror (`java.lang.Class`) objects
* Static field values (Java 8+ HotSpot)

Example:

```java
class Employee {
    int id;
}

Employee emp = new Employee();
```

Memory:

```text
Heap

+----------------------+
| Employee Object      |
|----------------------|
| id = 0               |
+----------------------+
```

Whenever an object is no longer reachable, the Garbage Collector reclaims its memory.

---

# Instance Variables

Instance variables belong to an individual object.

```java
class Student {

    int rollNo;
    String name;

}
```

Creating objects:

```java
Student s1 = new Student();
Student s2 = new Student();
```

Memory:

```text
Heap

+------------------+      +------------------+
| Student Object   |      | Student Object   |
|------------------|      |------------------|
| rollNo           |      | rollNo           |
| name             |      | name             |
+------------------+      +------------------+
```

Each object has its **own copy** of the instance variables.

Changing `s1.rollNo` does not affect `s2.rollNo`.

---

# Local Variables

Local variables exist only while a method is executing.

```java
void display() {

    int x = 10;
    String name = "John";

}
```

Memory:

```text
Stack

display()

+-------------------+
| x = 10            |
| name reference    |
+-------------------+
```

When the method finishes:

* The stack frame is destroyed.
* All local variables disappear automatically.

---

# Static Variables

Static variables belong to the **class**, not to objects.

```java
class Student {

    static String college = "ABC";

}
```

Creating multiple objects:

```java
Student s1 = new Student();
Student s2 = new Student();
Student s3 = new Student();
```

There is still only **one copy** of `college`.

---

# Where Were Static Variables Stored Before Java 8?

Before Java 8, HotSpot JVM had a memory region called **PermGen (Permanent Generation)**.

```text
Java 7

Heap
+----------------------+
| Objects              |
+----------------------+

PermGen
+----------------------+
| Class Metadata       |
| Static Variables     |
| Runtime Constant     |
| Interned Strings     |
+----------------------+
```

PermGen stored:

* Class metadata
* Static field values
* Runtime constant pool
* Interned strings

Since PermGen had a fixed size, applications could fail with:

```text
java.lang.OutOfMemoryError:
PermGen space
```

Large applications that dynamically loaded many classes (e.g., Spring, Hibernate, application servers) frequently encountered this problem.

---

# Why Was PermGen Removed?

PermGen had several limitations:

* Fixed maximum size
* Difficult memory tuning
* Frequent `OutOfMemoryError`
* Problems with dynamic class loading

To solve these issues, Java 8 introduced **Metaspace**.

---

# What Is Metaspace?

Metaspace replaced PermGen in Java 8.

Unlike PermGen, **Metaspace is allocated from native OS memory**, not from the Java Heap.

This means:

* It still uses your computer's **RAM**.
* But the memory is requested directly from the Operating System instead of being part of the Heap.

```text
Computer RAM
        │
        ├─────────────── Heap (JVM Managed)
        │
        └─────────────── Metaspace (Native OS Memory)
```

So the important distinction is:

* **Heap** → Managed by the JVM and Garbage Collector.
* **Metaspace** → Allocated from native OS memory and managed separately.

---

# What Does Metaspace Store?

Metaspace stores **class metadata**, including:

* Class names
* Field metadata
* Method metadata
* Method bytecode information
* Runtime constant pool
* Interface information
* Inheritance information
* Annotation metadata

**It does NOT store the values of static variables.**

---

# Then Where Are Static Variables Stored?

This is the part that surprises many Java developers.

Whenever a class is loaded, the JVM creates an object of type:

```java
java.lang.Class
```

Example:

```java
class Student {

}
```

Internally, the JVM creates something conceptually like:

```text
Student.class
```

This is an actual Java object.

Since every Java object lives in the Heap,

```text
Student.class
```

also lives in the Heap.

The static variables are associated with this **Class mirror object**.

Example:

```java
class Student {

    static int count = 10;

}
```

Conceptually:

```text
Heap

Student.class Object

+----------------------+
| static count = 10    |
+----------------------+
```

Every object accesses the same static variable through this shared `Class` object.

```text
Student s1
Student s2
Student s3

       │
       │
       ▼

Student.class Object

+----------------------+
| count = 10           |
+----------------------+
```

Changing:

```java
Student.count = 20;
```

immediately affects every object because only **one copy** exists.

> **Implementation Note:** The Java Language Specification defines the behavior of static fields but does not mandate their physical storage location. In the modern HotSpot JVM (Java 8+), static field values are associated with the `java.lang.Class` mirror object on the Heap, while the metadata describing those fields resides in Metaspace.

---

# Does Metaspace Use RAM?

Yes.

Everything inside a Java process ultimately uses your computer's **RAM**.

The difference is **who manages the memory**.

```text
Computer RAM

+------------------------------------------------+

Heap
↑
Managed by JVM Garbage Collector

Metaspace
↑
Allocated directly from Operating System

Thread Stacks
↑
Native Memory

Code Cache
↑
Native Memory

+------------------------------------------------+
```

So:

* Heap uses RAM.
* Metaspace also uses RAM.
* The difference is only the memory management mechanism.

---

# Can Metaspace Grow?

Yes.

Unlike PermGen, Metaspace automatically grows by requesting more native memory from the OS, until:

* available system memory is exhausted, or
* a configured limit is reached.

Example:

```bash
-XX:MaxMetaspaceSize=256m
```

If the limit is exceeded:

```text
java.lang.OutOfMemoryError: Metaspace
```

# Complete Comparison

| Feature          | Instance Variable                 | Static Variable                  | Local Variable       |
| ---------------- | --------------------------------- | -------------------------------- | -------------------- |
| Belongs to       | Object                            | Class                            | Method               |
| Number of Copies | One per object                    | One per class                    | One per method call  |
| Memory (Java 8+) | Heap                              | Heap (via `Class` mirror object) | Stack                |
| Lifetime         | Until object is garbage collected | Until class is unloaded          | Until method returns |
| Shared           | No                                | Yes                              | No                   |

---

# PermGen vs Metaspace

| Feature                       | PermGen (Java 7 and Earlier)      | Metaspace (Java 8+)           |
| ----------------------------- | --------------------------------- | ----------------------------- |
| Memory Location               | JVM-managed non-heap memory       | Native OS memory (RAM)        |
| Stores Class Metadata         | ✅                                 | ✅                             |
| Stores Method Metadata        | ✅                                 | ✅                             |
| Stores Runtime Constant Pool  | ✅                                 | ✅                             |
| Stores Static Field Values    | ✅ (historically in HotSpot)       | ❌                             |
| Static Field Values Stored In | PermGen                           | Heap (`Class` mirror object)  |
| Automatically Grows           | ❌                                 | ✅                             |
| Common Error                  | `OutOfMemoryError: PermGen space` | `OutOfMemoryError: Metaspace` |

---

# Final Summary

* **Heap** stores Java objects and is managed by the JVM's Garbage Collector.
* **Instance variables** are part of their objects, so they live in the Heap.
* **Local variables** live on the Thread Stack inside method stack frames.
* **Before Java 8**, HotSpot stored class metadata and static field values in **PermGen**.
* **Java 8 removed PermGen** and introduced **Metaspace**, which stores **class metadata** in **native OS memory (RAM)**.
* **Static field values are no longer stored in Metaspace.** In the modern HotSpot JVM, they are associated with the `java.lang.Class` mirror object, which itself is a Heap object.
* **Both Heap and Metaspace use your computer's RAM**, but Heap is managed by the JVM's Garbage Collector, while Metaspace is allocated from native OS memory.

> **The key concept to remember is:** **Metaspace stores information *about* classes (metadata), whereas the actual values of static fields live with the `Class` mirror object on the Heap in modern HotSpot JVMs (Java 8+).**
